## <a id="s2"></a>2. 功能 ID 细则（按原 §7 逐项）

### <a id="s2-tl"></a>2.1 上币时间线（TL-01 ~ TL-03）

**TL-01** 以日期为维度汇聚各交易所上币事件，支持 BD 回溯历史规律。已知字段：日期（UTC）、交易所名称、项目名称+Ticker、赛道名称（含父赛道）。`listing_events.stage` 枚举：`preannounce` / `spot` / `perp`。验收关注：每条记录含四项；stage 枚举以外值后端拒绝。

**TL-02** 项目名可点击跳转详情页。验收关注：任意项目名可跳转。

**TL-03** 按交易所/赛道筛选（P0 原文需求）；日期区间筛选为建议（原文建议/待确认）。筛选模式（单/多选、重置行为、排序、分页）原文未明确，见待决 [N01](#n01)。

### <a id="s2-pd"></a>2.2 项目详情页（PD-01 ~ PD-06）

**PD-01 / PD-02** MVP 后台手动录入基本面、赛道分类、用户量、收入（原文需求）；V2 对接龙哥系统，方式见 [O08](#o08)。评级是页面唯一观点内容。字段为空显示"暂无数据"（样式见 [N01](#n01)），不以 0 替代 null。

**PD-03** 展示声量三子项（KOL 发布记录、项目热度排名、核心人物曝光次数），并可追溯原帖（原文需求）。已知字段：`buzz_snapshots` — `kol_post_count`、`core_exposure_count`、`heat_score`、`track_rank`、`adjusted_total`（调整后总分）。三子项展示原始值，`adjusted_total` 展示调整后值，子项不可改（原文需求 AD-03）。

**PD-04** 展示各交易所每日现货成交额绝对值及同期同赛道排名（原文需求）。已知字段：`volume_snapshots`（明细）、`project_daily.total_spot_volume_usd`、`project_daily.volume_track_rank`。成交额口径（原文 §9.5 "24 小时成交额"为建议）见 [N03](#n03)。并列名次规则原文未明确，见 [N01](#n01)。V2 排名定义见 [O12](#o12)。

**PD-05** 同一时间轴叠加声量（`adjusted_total`）、交易量（`total_spot_volume_usd`）、币价（`project_daily.price_usd`）曲线，标注上币节点（原文需求）。节点悬停显示交易所、阶段、公告链接（公告链接可为空）。数据缺失日曲线行为见 [N05](#n05)。

**PD-06** P2 建议，格式与权限规则见 [N13](#n13)，待决前不细化。

### <a id="s2-rk"></a>2.3 声量排名（RK-01 ~ RK-03）

**RK-01** 公式 S(p,T) = Σ w(KOL等级ᵢ) × (a·浏览量ᵢ + b·收藏量ᵢ)，同赛道按 S 降序排名（原文需求）。a、b 系数与 KOL 等级权重均在后台配置；具体数值待 [O03](#o03)。多项目帖子分摊规则原文未明确，见 [N01](#n01)。

**RK-02** 不出跨赛道总榜，待 [O07](#o07) 最终确认。

**RK-03** 默认 7 天滚动，可选 1/7/30 天；多日合计使用调整后分数（原文需求）。可查看历史快照排名（查 `track_rank` 存储值，非重新计算）。多日缺日处理见 [N04](#n04)。

### <a id="s2-pt"></a>2.4 人物时间线回溯（PT-01 ~ PT-04）

**PT-01** 每人可打标签，枚举：`exchange_core` / `top_vc` / `whale` / `top_kol`；可按标签筛选（原文需求）。

**PT-02** M2 匹配器按别名/ticker/合约地址匹配帖子，`post_mentions.status = confirmed` 才进声量（原文需求，P0 后台能力）。人物停用/删除对历史快照的影响见 [N08](#n08)。

**PT-03 / PT-04** V2，本文不细化。

### <a id="s2-ad"></a>2.5 后台管理（AD-01 ~ AD-07）

**AD-01** 增删改人物；打标签（多标签可并存）；设 KOL 等级；变更后下次计算生效（原文需求）。停用/删除后历史快照影响见 [N08](#n08)。

**AD-02** 修改权重/系数后可重算排名；改动留审计日志（原文需求）。版本管理方式原文未明确，见 [N01](#n01)。

**AD-03** 仅允许调整 `buzz_snapshots` 总分，三子项为只读原始值（原文需求）。原始值与调整值分开存储，记录操作日志，调整后前台生效，可还原（原文需求）。无原始数据时的调分行为、`reason` 字段是否强制、撤销定义见 [N10](#n10)。

**AD-04** 手工录入项目与上币事件（原文需求）；批量导入为建议。必填：项目名、Ticker、赛道（需存在）；上币事件必填：项目、交易所、日期（UTC YYYY-MM-DD）、阶段枚举。stage 枚举以外的值返回 400。

**AD-05** 增删改别名（ticker/项目名/合约地址）；保存后新采集帖子按新别名匹配；变更记入操作日志（原文需求）。历史帖子是否需要重新文本匹配见 [N09](#n09)。

**AD-06** 仅 ticker 命中且存在同名 ticker 时进待确认队列；确认前 `pending` 不计入声量（原文 §9.5 建议/待确认）；确认后触发重算；驳回不计入声量（原文需求）。

**AD-07 赛道** 维护父子赛道结构；调整赛道触发重算并留痕（原文需求）。删除有项目/快照/子赛道引用的赛道返回错误（原文需求）。赛道层级深度见 [N11](#n11)。
**AD-07 账号** 管理员可新增/停用内部账号，停用后无法登录，不能停用自己（原文需求）。

### <a id="s2-ac"></a>2.6 访问权限（AC-01 ~ AC-03）

**AC-01** 未授权无法访问任何数据页面（原文需求）。**AC-03** 后台服务端校验权限，非仅前端隐藏（原文需求）。editor/viewer 访问范围区别见 [N12](#n12)。
**AC-01b / AC-02** V2，本文不细化。

## <a id="s5"></a>5. 实现说明

实现现状详见 [`../DATA_SOURCES.md`](../DATA_SOURCES.md)。

以下行为仅由代码实现证明，**不等于正式需求**，在 [§4](#s4) 对应待决项决策前不写入验收标准：

- M3 `manual_backfill` 重算范围（读已有 mention 行，不重跑 M2 文本匹配）

**历史回算 ≠ 历史重匹配：** `manual_backfill` 触发的是 M3 对已有 `post_mentions` 行重新计算声量分，不对历史帖子原文重新执行 M2 别名文本匹配。两者是独立操作，混淆会导致对 AD-05 的错误验收预期。
